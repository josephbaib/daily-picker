# Daily Picker — дизайн первой версии

Дата: 2026-09-08. Статус: на проверке у Юсуфа.

## 1. Зачем

Команда бизнес-помощника в Сбере каждое утро проводит дейлик в видеозвонке. Слово берут по очереди, и каждый раз возникает пауза «кто следующий». Нужна веб-игра, которая за 10–40 секунд весело выбирает, кто говорит первым и в каком порядке идут остальные. Сейчас в звонке 6 человек, может быть до 20.

Ресёрч лежит в `research-result.md`. Главный вывод: шаринг экрана в звонке даёт задержку 1–3 секунды и мыло, поэтому игра проектируется под лаг, а желающие открывают ссылку у себя и видят ту же игру синхронно.

## 2. Решения, принятые в брифе

| Вопрос | Решение |
|---|---|
| Как смотрят | Гибрид: ведущий шарит экран, игра спроектирована под лаг; кто открыл ссылку, видит то же самое у себя синхронно |
| Кто запускает | Ведущий меняется, запустить может любой, кто открыл ссылку |
| Список участников | Редактируется на странице игры, общий для всех, хранится в базе |
| Память между днями | Есть: кто был первым вчера, сегодня первым не будет |
| Ссылка | Одна навсегда, вида `https://josephbaib.github.io/daily-picker/?room=<имя>` |
| Хостинг | GitHub Pages из репозитория `josephbaib/daily-picker`, публичный |
| Бэкенд | Supabase, бесплатный тариф, регион Europe. URL и publishable key в `SUPABASE.md` |
| Корпоративная сеть | Может блокировать GitHub Pages и Supabase. Принято как риск, обход не делаем |
| Игры первой версии | Гонка и «Последний выживший», обе дают полный порядок |
| Стиль | А: 16-битный платформер. Б (HD-2D) и В (PS1) добавляются позже как темы |
| Стек | Ванильный JS модулями без сборки, Canvas для сцен, Supabase через CDN |

Канвас с направлениями стиля: https://claude.ai/code/artifact/0cb52d1c-70cc-4586-8734-0cc03000740a. Наброски сцен и скрипт их отрисовки лежат в `docs/design-directions/`.

## 3. Архитектура

Статическая страница на GitHub Pages плюс Supabase для данных и реалтайма.

```
index.html
css/app.css
js/app.js            точка входа, состояние экрана
js/db.js             Supabase: чтение и запись комнаты, история, подписки, канал старта
js/rng.js            генератор случайных чисел по сиду (Mulberry32)
js/order.js          расчёт порядка выступлений с правилами честности
js/avatar.js         генерация пиксельного героя из имени
js/sound.js          чиптюн через Web Audio, без файлов
js/games/index.js    реестр игр и режим «случайная игра»
js/games/race.js     гонка
js/games/survivor.js последний выживший
js/themes/index.js   реестр тем
js/themes/pixel16.js тема А: палитра, фоны, тайлы, спрайты
js/ui/participants.js панель участников
js/ui/result.js      финальный экран
supabase/migrations/0001_init.sql
tests/*.test.js      node --test
```

Принцип: **итог считается до анимации**. Из сида и истории получаем порядок, потом игра разыгрывает анимацию так, чтобы прийти к нему. Подвисшая или отставшая картинка исход не меняет.

## 4. Данные

Таблица `rooms`:

| Поле | Тип | Что это |
|---|---|---|
| id | text, первичный ключ | имя комнаты из ссылки, латиница, цифры, дефис |
| participants | jsonb | массив `{id, name, present}`; `id` короткий случайный, чтобы переименование не ломало историю |
| settings | jsonb | `{theme, sound, crt}` общие настройки комнаты |
| updated_at | timestamptz | для подписки на изменения |

Таблица `games`:

| Поле | Тип | Что это |
|---|---|---|
| id | uuid | |
| room_id | text | ссылка на комнату |
| played_at | timestamptz | |
| game | text | `race`, `survivor` |
| seed | integer | сид, от которого посчитан порядок |
| order_ids | jsonb | массив id участников в порядке выступления |
| started_by | text | необязательная подпись, кто нажал старт |

Права доступа: на обеих таблицах включён RLS, роли `anon` разрешены чтение, вставка и обновление. Удаление комнат запрещено всем через API. Это командная игра, ссылка не публикуется, защита от случайной порчи важнее защиты от злого умысла.

Миграция лежит в `supabase/migrations/0001_init.sql`. Применяется GitHub-интеграцией Supabase при пуше в main. Если интеграция на бесплатном тарифе не срабатывает, Юсуф вставляет файл в SQL Editor вручную.

## 5. Синхронизация

Два слоя, оба через Supabase.

1. **Состояние комнаты.** При открытии страница читает `rooms` по id из ссылки и последние 30 записей `games`. Подписка `postgres_changes` на свою комнату: изменения списка участников и новые игры приходят всем открывшим.
2. **Старт игры.** Кто нажал «Старт», тот делает: генерирует сид, считает порядок, вставляет запись в `games`, шлёт в broadcast-канал `room:<id>` событие `start` с полями `{gameId, game, seed, startAt}`, где `startAt` это серверное время плюс 3 секунды. Все получившие событие запускают обратный отсчёт до `startAt` по своим часам, поправленным на разницу с сервером (разница меряется один раз при загрузке по времени ответа Supabase). У ведущего игра запускается тем же путём, через собственный канал, чтобы код был один.

Если событие потерялось, страница всё равно увидит новую запись в `games` по подписке и покажет результат без анимации с пометкой «игра уже прошла».

Если Supabase недоступен: страница показывает предупреждение, список берётся из последней копии в localStorage, игру можно запустить локально без записи в историю.

## 6. Расчёт порядка

Вход: список присутствующих участников, история игр комнаты, сид. Выход: массив id.

1. Берём присутствующих. Если их 0, старт недоступен. Если 1, порядок из одного.
2. Первое место. Кандидаты все присутствующие. Если присутствующих 3 и больше, исключаем того, кто был первым в последней сыгранной игре. Вес кандидата: `1 + число игр с момента, когда он последний раз был первым` (никогда не был первым: вес как у самого давнего плюс один). Тянем взвешенно по сиду.
3. Остальные места: перемешивание Фишера-Йетса по тому же сиду.

Правило прозрачное и показывается на финальном экране строкой «Вчера первым был …». Никаких лидербордов и штрафов.

Генератор: Mulberry32, сид 32-битное целое. Один и тот же сид и список дают один и тот же порядок в любом браузере, это проверяется тестом.

## 7. Игры

Контракт игры, файл в `js/games/`:

```js
export default {
  id: 'race',
  title: 'Гонка',
  duration: 12,                       // секунд от старта до замирания
  minPlayers: 2, maxPlayers: 20,
  play({ canvas, theme, participants, order, seed, onFrame, onFreeze })
}
```

Игра получает готовый порядок и сид, рисует на Canvas, по окончании вызывает `onFreeze`. Дальше общий сценарий: замирание, отсчёт 3-2-1, финальный экран. Общий код не знает, какая игра идёт.

**Гонка.** Горизонтальные дорожки, параллакс-фон темы, факелы, финиш с клетчатым флагом. 10–12 секунд. Траектории строятся от сида: лидер меняется 2–3 раза, последние 3 секунды замедление и выстраивание в рассчитанный порядок. При 11 и больше участниках дорожки в два ряда, спрайты того же размера, камера следит за лидером.

**Последний выживший.** Участники карточками с героями в сетке. Каждые 1–1.5 секунды один выбывает с пиксельным взрывом, порядок выбывания это обратный порядок выступлений. Последний оставшийся говорит первым. При 20 участниках первые выбывания идут по 0.5 секунды, последние три по 2 секунды, общая длительность не больше 20 секунд.

**Случайная игра.** Кнопка, которая выбирает игру из реестра по сиду. Событие `start` несёт уже выбранную игру.

## 8. Темы

Контракт темы, файл в `js/themes/`: палитра, функция отрисовки фона для гонки, функция отрисовки карточки для выжившего, спрайты героев, шрифт. Первая тема `pixel16`. Ассеты рисуются кодом или берутся из бесплатных наборов с лицензией CC0 и лежат в `assets/` как PNG; источник и лицензия каждого набора записываются в `assets/CREDITS.md`.

Правила под лаг, обязательные для всех тем: крупные объекты, длинная фаза замедления, статичный финальный экран, результат всегда текстом.

## 9. Герой из имени

Хэш имени задаёт причёску (6 вариантов), цвет волос, цвет одежды, цвет штанов из палитры темы. Одно имя всегда даёт одного героя. Герой показывается в панели участников, в игре и на финальном экране. Спрайт 12×16 пикселей, рисуется с масштабом 4–6.

## 10. Интерфейс

Один экран, шрифт Press Start 2P с запасным monospace, всё на русском.

- **Панель участников** слева, сворачивается. Строки: герой, имя, переключатель «сегодня нет». Кнопка «Добавить», редактирование имени по клику, удаление с подтверждением. Внизу «Вчера первым был …».
- **Сцена** справа: выбор игры (гонка, последний выживший, случайная), кнопка «Старт», Canvas. Кнопка недоступна, пока присутствующих меньше двух.
- **Финальный экран**: «Первым говорит», имя крупно, ниже полный порядок, конфетти, строка про вчера. Закрывается пробелом или кликом.
- **Угол экрана**: звук вкл/выкл, переключатель «телевизор» (полосы развёртки поверх сцены, выключен по умолчанию), копирование ссылки.
- **Без комнаты** в адресе: экран с одним полем «Имя комнаты» и кнопкой «Создать или открыть».

Крупные кнопки и текст от 16 px, чтобы читалось через шаринг экрана.

## 11. Звук

Web Audio, синтез в браузере: щелчки отсчёта, дробь во время замедления, туш на раскрытии, короткие писки при выбывании. Файлов нет. По умолчанию выключен, выбор хранится в localStorage. Ничего не зависит от звука, всё продублировано визуально.

## 12. Тесты

`node --test tests/`, без зависимостей:

- `rng.test.js`: один сид даёт одну последовательность; разные сиды разные.
- `order.test.js`: воспроизводимость; первый из прошлой игры не первый сейчас при 3+; при 2 участниках правило не применяется; на 1 и на 20 участниках порядок полный без повторов; веса растут для давно не начинавших.
- `avatar.test.js`: одно имя даёт один герой; разные имена дают разные в большинстве случаев.

Анимации, синхронизация и Supabase проверяются руками в браузере и на первом дейлике.

## 13. Деплой

- GitHub Pages из ветки main, корень репозитория. Включается через настройки репозитория.
- Supabase URL и publishable key зашиты в `js/config.js`.
- Миграции через GitHub-интеграцию Supabase, запасной путь через SQL Editor.

## 14. Первый живой прогон: что проверить

1. Открывается ли ссылка из корпоративной сети, у кого именно нет.
2. Заметен ли разъезд старта у тех, кто открыл у себя.
3. Читаются ли имена и герои через шаринг экрана.
4. Хватает ли финального экрана без звука.
5. Не дольше ли 40 секунд от нажатия до результата.

## 15. Не делаем в первой версии

Темы Б и В, телефон как контроллер, статистика и серии, коррекция часов через timesync, экспорт истории, авторизация.
